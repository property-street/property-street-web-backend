# Notification logic
<!--client(regular/agent)-->

## NB
Lazy priotized notification like asset-request agent notification is persisted on a zset for 7 days (for agents that might not get the update because they are not connected).

## on reconnection
When a client(regular/agent) is reconnecting, reconnection should be made with the last notification timestamp if possible.

## pending notification dispatch
<!--This is for cases when a client reconnects to the server-->
If a timestamp is not provided, a new timestamp is gotten by retrieving the last timestamp of the user's Notification instances.

- If timestamp exist, 
    - For agents: The timestamp is used to check against existing entries. If the timestamp exists in the zset, entries from the zset up till the last entry is pinged to the user's frontend.
    - For regular: The user's pend pool should be checked if any notification got sent. If there is, the notification_ids from the pool is gotten, those ids are used to query the database, and those objects are pinged to the user. Delete the `pending_notifications` field of the user's pend pool hset.
- else if None
    - For agents: All notification objects in the agent_only notification is pinged to the user.
    - For regular: Nth happens
